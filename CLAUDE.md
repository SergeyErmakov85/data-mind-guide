# CLAUDE.md — Математическая статистика для психологов (data-mind-guide)

> Инструкция по оформлению и визуализации для AI-ассистентов (Lovable, Cursor, Claude Code).
> Сайт: https://data-mind-guide.lovable.app/ — интерактивная образовательная платформа по
> математической статистике для психологов.
>
> **Цель:** изменить **только дизайн и стиль** (визуальный язык, типографику, эффекты, анимацию,
> компоновку, визуализации) — в духе «Kinetic Minimalism + Futuristic UI».
> **Контент остаётся как есть.** **Цветовая палитра остаётся как на сайте.**

---

## 0. Два нерушимых правила

1. **КОНТЕНТ НЕ МЕНЯЕТСЯ.** Тексты, формулы, термины, структура разделов, порядок и состав
   материалов остаются прежними. Запрещено переписывать, сокращать, дополнять или удалять
   содержательную информацию. Меняется только её визуальная подача.
2. **ПАЛИТРА НЕ МЕНЯЕТСЯ.** Цвета берутся **из существующих токенов проекта** (см. §2). Новые
   hex’ы не вводятся. Весь новый стиль (свечения, градиенты, состояния) строится **поверх уже
   существующих цветов**.

Всё остальное — типографика, компоновка, тени/свечения, скругления, анимации, стиль компонентов,
визуализации — приводится к новому языку дизайна, описанному ниже.

## 2. Цветовая палитра — заморожена (источник истины)

Палитра уже задана в проекте. **Не меняй значения цветов.** Источник истины:

- `src/index.css` — CSS-переменные shadcn в блоках `:root` и `.dark`
  (`--background`, `--foreground`, `--card`, `--primary`, `--secondary`, `--muted`, `--accent`,
  `--border`, `--ring` и т.д.).
- `tailwind.config.ts` — маппинг этих переменных в Tailwind-классы.

Правила работы с цветом:
- Используй **только** существующие токены (`bg-background`, `text-foreground`, `bg-card`,
  `text-primary`, `border-border` и т.п.). Никаких новых hex-констант в компонентах.
- Свечения/градиенты/состояния (`hover`, `active`) строй на **тех же** токенах через прозрачность
  (например, `box-shadow: 0 0 16px hsl(var(--primary) / 0.35)`), а не новым цветом.
- Если для эффекта нужен «приглушённый» вариант цвета — бери тот же токен с альфой, а не подбирай
  новый оттенок.
- Светлая/тёмная тема: сохраняй обе, если они есть. Меняется стилистика, не цветовая семантика.

## 3. Язык дизайна, который применяем: «Kinetic Minimalism + Futuristic UI»

Это **стилистика**, накладываемая поверх существующих цветов:

- **Glassmorphism-карточки:** фон `bg-card` с лёгкой прозрачностью, тонкая граница
  `1px solid hsl(var(--border))`, мягкое скругление (14px / 8px), тень
  `0 4px 24px rgba(0,0,0,0.3)`. Эффект «стекла», а не плоской заливки.
- **Свечения (glow):** на акцентных/активных элементах — `box-shadow` цветом `--primary`/`--accent`
  с низкой альфой. Активная граница — токен с альфой ~0.4, активный фон — ~0.08–0.12.
- **Фоновые градиентные «блобы»:** `position: fixed`, большие круги с радиальным градиентом из
  `--primary`/`--accent` очень низкой альфы (~0.02–0.04), `pointer-events: none`. Создают глубину,
  не отвлекая.
- **Минимализм:** много воздуха, тонкие границы, низкие альфы; акцент создаётся свечением и
  типографикой, а не плотной заливкой.
- **Кинетика:** плавные переходы `transition: all 0.3s cubic-bezier(0.22,1,0.36,1)` на hover/active;
  лёгкая «живость» интерактивных визуализаций (пульсация акцентов, анимация появления). Без резких
  скачков и навязчивого движения.

### Типографика (часть нового стиля)
- **Заголовки и лейблы секций** — геометрический дисплейный шрифт (**Orbitron** или близкий),
  капс, широкий трекинг (`letter-spacing: 0.12–0.18em`, `uppercase`).
- **Формулы, числа, код, значения контролов** — моноширинный (**JetBrains Mono**).
- **Основной текст** — чистый гуманистический sans (**IBM Plex Sans / Inter**), `line-height` 1.7–1.8.
- Подключение — через Google Fonts. Шрифты — это стиль, их менять можно (в отличие от цвета и контента).

### Читаемость (критично)
- В визуализациях и поверх тёмных зон используй **более яркий/светлый** вариант текстового токена
  (`--foreground`), а не приглушённый (`--muted`), для важных подписей — максимум контраста.

## 4. Компоновка и компоненты

- **Шапка:** лого/название платформы слева, краткие метрики/навигация справа, нижняя граница
  `--border`.
- **Раскладка тем/материалов:** где уместно — боковая панель контролов (≈320px, `overflow-y:auto`,
  секции разделены `border-top`) + основная область с визуализацией и пояснениями. Сохраняй
  существующую информационную структуру, меняй только её визуальное оформление.
- **Компоненты shadcn** перестилизуй под новый язык (стеклянные карточки, свечения, mono-значения,
  Orbitron-капс лейблы), но **не меняй их поведение и данные**.
- Переиспользуй единые паттерны: лейбл = Orbitron-капс; значение = mono; границы/свечения = токены.
  Не плоди дубликаты компонентов с разной стилистикой.

## 5. Визуализации (для статистики — ключевое)

Платформа про статистику, поэтому графики/распределения/симуляции — сердце визуальной подачи.

### Правила
- **Только JSX/React** для интерактива (слайдеры выборки/параметров, тогглы, hover-подсказки).
  Статический SVG — лишь для неинтерактивных схем.
- Типовые визуализации: распределения (нормальное, t, χ², F), гистограммы, диаграммы рассеяния,
  доверительные интервалы, p-value, регрессия, бутстрэп/симуляции. Делай их **интерактивными**
  (параметры меняются слайдерами, график реагирует в реальном времени).
- Цвета графиков — **только** из токенов палитры (`--primary`, `--accent`, `--secondary`,
  `--muted`).

### Подводные камни canvas (запомнить!)
- **`ctx.roundRect()` падает** в canvas/artifact-окружении — используй `fillRect`.
- Состояние тогглов/переключателей внутри анимационного цикла читай через **`useRef`, а не
  `useState`** — замыкание в `requestAnimationFrame` должно видеть актуальное значение. Передавай в
  canvas именно ref-ы.
- Поддерживай **DPR**: масштабируй canvas под `window.devicePixelRatio` + `setTransform(dpr,…)`.
- При структурном изменении данных пере-инициализируй canvas через `key`-приём.
- **Если canvas повторно падает — не упорствуй. Перестрой визуализацию на чистом HTML/CSS/SVG.**

## 6. Математика

- Все формулы — через **KaTeX/LaTeX**. Если в проекте есть компонент-обёртка для рендера формул —
  используй её; если нет — заведи единый компонент `Math`.
- **Никаких «голых» Unicode-символов** (σ, μ, χ², Σ, √ и т.п.) в финальном рендере разметки —
  только KaTeX. (Исключение — текст внутри `<canvas>`, где KaTeX не рендерится.)
- Сами формулы (их математическое содержание) **не меняй** — только способ рендера/оформления.

## 7. Перекрёстные ссылки «как в Википедии» (если применимо)

Если в проекте есть взаимосвязанные темы/страницы (например, тема ссылается на разбор понятия в
другом разделе) — связывай их **двунаправленно**, по принципу Википедии:
- из текста темы — ссылка в **конкретное место** (`#anchor`) страницы с подробным разбором понятия;
- со страницы разбора — ссылка **обратно** к месту, откуда пришёл ученик.
- Реализация — через единый компонент-ссылку с неоновым стилем; у секций-целей должны быть
  стабильные `id` (не менять — иначе ломаются входящие ссылки).

*(Не выдумывай эту структуру, если её нет в проекте. Это паттерн на случай, когда взаимосвязи между
материалами уже существуют или планируются.)*

## 8. Язык и терминология

- UI — на **русском**.
- Для раздела курса/материала используй слово **«раздел»**, **не «модуль»**.
- Сохраняй существующую терминологию контента без изменений.

## 9. Workflow в Lovable

- Промпты — **последовательные, самодостаточные**, с полным включением нужного контента/контекста.
- Чекпоинты commit-and-preview каждые **2–3 промпта**; применяй по одному промпту и проверяй результат.
- Стилизуй **итеративно, по компонентам/страницам** — не переписывай всё разом, чтобы не задеть контент.
- При ошибке Lovable — **корректирующий промпт под конкретный файл**, а не переписывание всего предыдущего.
- Аудит-рекомендации сначала проверяй на совместимость с Lovable; неприменимое (напр. GitHub Actions CI) — пропускай.

## 10. Чек-лист для любого изменения

- [ ] Контент не изменён (тексты, формулы, термины, структура — на месте).
- [ ] Цвета — только из существующих токенов; новых hex’ов нет; обе темы сохранены.
- [ ] Карточки — glassmorphism (`bg-card` + `--border` + скругление + мягкая тень).
- [ ] Свечения/градиенты/состояния построены на токенах через альфу, не новым цветом.
- [ ] Заголовки — Orbitron-капс; текст — sans; формулы/числа/код — mono.
- [ ] Важные подписи поверх тёмных зон — яркий `--foreground`, не `--muted`.
- [ ] Интерактив — React/JSX; для canvas соблюдены правила §5.
- [ ] Формулы — KaTeX, без сырого Unicode; математика по содержанию не тронута.
- [ ] Переходы — `cubic-bezier(0.22,1,0.36,1)`, без резких скачков.
- [ ] Слово «раздел», не «модуль».
- [ ] (Если есть взаимосвязи материалов) двунаправленные ссылки на стабильные `id`.
